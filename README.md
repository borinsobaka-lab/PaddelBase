# PaddelBase

Веб-приложение для организации игр в падел в Грузии: заявки на матчи, турниры
(Американо, Мексикано и их командные версии), рейтинг игроков, лента комьюнити.

Первый канал дистрибуции — Telegram Web App, вёрстка mobile-first.

## Структура репозитория

```
packages/rating       — движок рейтинга, чистая логика   ✔
packages/tournament   — генераторы сеток, чистая логика  ✔
packages/db           — Prisma-схема и клиент            ✔
packages/core         — доменные операции над БД          ✔
apps/web              — Next.js приложение              ✔
```

`packages/rating` и `packages/tournament` не импортируют ничего из `web` и `db`:
принимают простые объекты, возвращают простые объекты. Это условие
тестируемости и возможности пересчитать всю историю рейтинга при изменении
формулы.

## Команды

```bash
pnpm install
pnpm db:generate && pnpm db:deploy && pnpm db:seed
pnpm dev          # http://localhost:3000

pnpm test         # все пакеты
pnpm typecheck
```

### Вход

На время тестирования вход делается по одному имени: вводите имя — заходите под
ним. Это **не авторизация**: совпадение имён означает вход в чужой профиль, а
подпись на куке защищает только от подмены идентификатора руками. Вся логика
собрана в `apps/web/src/lib/session.ts` и `signInByName`, поэтому переход на
Telegram, Google или что-то ещё меняет только их — экраны не трогаются.

### Интеграционные тесты

Часть тестов `packages/core` работает против настоящего PostgreSQL — логика
опирается на транзакции и запросы по связям, подменять это заглушкой
бессмысленно. Без `TEST_DATABASE_URL` они пропускаются:

```bash
createdb paddelbase_test
export TEST_DATABASE_URL=postgresql://localhost:5432/paddelbase_test
DATABASE_URL=$TEST_DATABASE_URL DIRECT_URL=$TEST_DATABASE_URL pnpm db:deploy
pnpm --filter @paddelbase/core test
```

## База данных

```bash
cp .env.example .env      # заполнить DATABASE_URL и DIRECT_URL из Supabase
pnpm db:generate          # Prisma Client
pnpm db:deploy            # применить миграции
pnpm db:seed              # заглушки кортов и тестовые игроки
```

`DATABASE_URL` — пулер Supabase на порту 6543 обязательно с `?pgbouncer=true`;
`DIRECT_URL` — прямое соединение на 5432, его использует только миграция.

Таблицы живут в схеме `app`, а не в `public`: `public` публикуется наружу через
PostgREST по публичному anon-ключу, а Prisma создаёт таблицы без RLS.

Справочник кортов (`packages/db/prisma/courts.ts`) — **временный**: районы и
города вместо реальных клубов, без координат. Заменить до запуска; сид работает
по upsert'у, поэтому правка файла и повторный `pnpm db:seed` обновят записи.

## Экраны

Готово: вход, анкета, главная, лента игр, создание матча, экран матча с вводом
и подтверждением счёта, создание турнира, экран турнира со вкладками
(информация, участники, раунды, таблица), лента комьюнити с постами, фото,
лайками и комментариями, уведомления, профиль с историей.

Тема светлая. ТЗ §9 предлагало тёмную, аргументируя чтением на солнце, поэтому
солнце отрабатывается иначе: фон не чисто-белый, контраст держится выше
минимума, карточки различимы границами, а не тенями — тени на ярком свете
пропадают первыми. Акцент из ТЗ (`#3DDC84`) пришлось углубить до `#0A7A42`:
на белом он давал для белого текста контраст около 1.5:1, кнопка была бы
нечитаемой.

## Стартовый уровень

Анкета из десяти вопросов (`packages/rating/src/onboarding.ts`). Основа —
поведенческие технические якоря: работа со стеклом, удары над головой, подача,
позиционирование. Стаж, частота, тренер, ракеточное прошлое и турнирный опыт
работают модификаторами, прямая самооценка входит с весом 0.15 и служит
детектором завышения.

Так сделано потому, что прямая самооценка — худший из доступных предикторов:
слабые игроки систематически завышают себя, сильные занижают, и шкалу каждый
понимает по-своему. Отсюда же поправки: −0.3 новичкам, −0.5 уверенным
любителям, коридор 2.5–3.5 бывшим сильным ракеточникам и потолок 5.0 — выше
только через сыгранные матчи.

Стартовая надёжность 20 %: анкета не верифицирована, поэтому первые матчи
двигают уровень крупно, а к 8 матчам уровень считается подтверждённым.

## Медиа

Фото и видео проходят через `apps/web/src/lib/storage.ts` — один интерфейс с
двумя адаптерами. В продакшене Supabase Storage, локально файлы кладутся на
диск, чтобы разработка не требовала облачных ключей.

Продакшен-сборка без `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` падает
намеренно: молча писать на диск контейнера значит потерять все загруженные
файлы при первом перезапуске, и заметит это игрок, а не разработчик. Для
локального прогона production-сборки есть явный опт-ин `MEDIA_STORAGE=local`.

Фото ужимаются до 1600 px по длинной стороне на клиенте: снимок с телефона —
это 3–6 МБ ради картинки, которая показывается в ленте шириной 390 px.

## Метрики

Без них коэффициенты §3.8 нельзя откалибровать — сейчас все они инженерная
реконструкция:

```bash
pnpm rating:metrics                 # отчёт за всю историю
pnpm rating:metrics --from=2026-06-01
pnpm rating:metrics --json
```

Ключевая цифра — качество предсказания: целевой коридор 60–70 %. Выше означает,
что матчи слишком неравные, ниже — что модель не работает.

## Пересчёт рейтинга

Движок — чистая функция, а по каждому событию хранится снимок «до», поэтому всю
историю можно переиграть по изменившимся коэффициентам:

```bash
pnpm rating:recompute --dry-run            # посчитать и показать масштаб сдвига
pnpm rating:recompute --from=2026-08-01    # только с даты
pnpm rating:recompute                      # вся история
```

Пересчёт идёт в одной транзакции: либо переписывается вся история, либо не
меняется ничего. Любое изменение констант в `packages/rating/src/config.ts`
обязано сопровождаться повышением `RATING_CONFIG_VERSION` и пересчётом.
